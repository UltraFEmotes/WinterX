# Release checklist

Before the final public release, remove the three development test tweaks from Ruby's catalogue and the built-in repository index and packages. The development builds may keep them for testing. Verify that no test entries appear in browsing, search, local imports bundled with the release, or the default source. Preserve users' installed test data and do not silently uninstall anything.

Verify repository, update, removal, Safe Mode and recovery flows on supported devices, review third-party assets and licensing, and update the public documentation to match the features actually shipped.

Built-in tweaks with preferences must expose them in **Spring's actual Settings app**, using native iOS 6 styling. Check Animaper, ColoredBar, SnowyHome's packs/import/badges/labels/corners, SSH's Start/Stop/authentication and Message+'s native Messages Settings/photo controls. A Ruby-only preferences screen does not satisfy this requirement. Verify actual delivery before claiming new Messages transports.

The experimental source/docs update, including independently authored executable-tweak support, is authorized; current work is not limited to alpha8. Do not describe packaged checks as live verification or a hardened sandbox. Never publish the executable developer example, layout drafts or test tweaks in the working built-in index. Full native-limit, update/uninstall, Safe Mode and recovery trials remain required before calling the runtime stable. Exclude APKs, companion binaries, SDKs, personal data, backups, user-supplied icon artwork/packs and private handoff records from source publication.

The prepared SSH-terminal/snowflake engine retains the original five tweak pins, renderer/folder fixes, Barrel and guarded app actions; its latest backup preserved all **485 current entries**. It adds a blue-snowflake report and interactive WinterX prompt. Packaged/spied checks pass; live terminal/rendering/delivery and signing-compatible Android deployment still need trials. Video/reactions, broader home APIs and rooted/rootless work remain unfinished. Rootless must include a limited no-Shizuku baseline; local transport checks do not establish universal support. Keep unfinished drafts/examples outside working catalogues and publish source/docs only.
